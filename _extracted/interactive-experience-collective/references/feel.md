# 気持ちよさの設計 — 身体・映像・音がどう連動すると生理に効くのか

<!-- volatile: 2026-08 — ハプティクスの実装手段（Core Haptics / Vibration API / LRA の仕様）、prefers-reduced-motion 等の対応状況、フレームレートの実現可能帯。知覚の閾値と生理反応は対象外（人間の側は変わらない）。 -->

「説明されなくても、触った瞬間に良いと思える」は感性の問題ではなく**設計対象**である。ここに書くのは、身体の動き・映像・音（および補助としての触覚）が**どう時間的に連動すると生理的な快が出るか**の原理と数値。

`protocol.md` Step 3 が「何が起きるか」の設計なら、これは「**それがどう感じられるか**」の設計である。Step 8 の検証項目「その行為が気持ちいいか」に答えられないプロトタイプは、技術的に動いていても失敗している。

## 1. 「気持ちいい」を6つに分ける — 一語で扱うと設計できない

ユーザーが「気持ちいい」と言う時、機序の違う別のものを指している。**まずどれを狙うかを決める。**

| 快の型 | ユーザーの言葉 | 機序 | 主に効く設計変数 | これを壊すもの |
|---|---|---|---|---|
| **主体感** | 「効いてる」「反応する」 | 予測との一致 + 時間的近接 | 遅延とその**安定性**、写像の一貫性 | ジッタ、無反応、勝手に動く自動演出 |
| **律動** | 「クセになる」「乗れる」 | 予測と誤差の最適点、運動同期 | テンポ、シンコペーション、判定窓 | 完全な規則性／完全な乱数 |
| **賦活** | 「すごい」「アガる」 | 覚醒の上昇と報酬予期 | 密度、テンポ、帯域、コントラスト、カメラ | 上げっぱなし、主体感のない派手さ |
| **鎮静** | 「落ち着く」「癒される」 | 副交感優位、呼吸・心拍への同調 | 呼吸周期、呼気優位、下降、低域 | トリガの多発、点滅、鋭いアタック |
| **美** | 「綺麗」 | 処理流暢性（読み取りやすさ） | コントラスト、対称、丸み、運動曲線、色数 | 情報過多、等速直線運動 |
| **楽しさ** | 「もう一回」 | 有能感と自律性（瞬間ではなく反復） | 上達の余地、選択、表現の解像度 | 天井の低い操作 |

**最重要の判断:** 覚醒を**上げる**のか**下げる**のかを決めずに「気持ちよくする」と、賦活の手段（点滅、シェイク、密度）と鎮静の手段（持続、下降、低域）が混ざって両方死ぬ。1つの体験に両方を入れるのは正しいが、**同時刻には片方。**

主体感はこの表の中で特別である。**他の5つは主体感の上に乗る。**自分がやった感じのしない律動は他人の音楽、主体感のない賦活は騒音になる。

## 2. 主体感（sense of agency）— 土台。ここが崩れると他は全部無効

自分がやったという感覚は、3つの条件から生まれる。**予測どおりであること / 時間的に近いこと / 選べたこと。**設計で操作できるのは主にこの3つ全部である。

### 遅延の閾値 — 入力の種類で桁が違う

| 入力と応答の関係 | 上限の目安 | 根拠 |
|---|---|---|
| **指で直接つかんで動かす**（ドラッグ、押し込み、直接操作） | **知覚は 6ms 程度から。25ms 超で操作精度が落ちる** | 直接接触では自分の指が基準になるため、最も厳しい |
| 離散トリガ → 反応（タップして何かが起きる） | 24ms 以下なら遅延を知覚できない | 上と同じデバイスでも、離散なら4倍甘い |
| 自分の動作が音を出す（楽器的） | 20〜30ms | `sound.md` 第3節 |
| 演者が身体の延長として感じる | 50ms 前後 | `movement.md` 第6節 |
| 観客・一般の視覚的インタラクション | 100ms 前後 | |
| **「実時間で応じている」と感じる限界** | **400ms** | これを超えると応答ではなく処理待ちになる |
| 身体所有感（自分の分身・アバターとして感じる） | **300ms** を超えると崩れる | 視覚と体感の統合窓 |

**同じ体験の中でも、直接操作している要素だけは別枠で速くする。**画面全体が 80ms でも、指の下にある1要素が 20ms で追従していれば、体験全体が速く感じられる。人は**最速の層**で応答性を判断する。

### 一定の遅延は身体が校正する。ジッタは校正できない

これが実装上もっとも見落とされる。人間は一定のラグに適応する（150ms のラグに晒されると、タップを 20ms ほど早めるようになる）。**適応が済めば主体感は戻る。**一定であれば 200〜300ms でも体験が壊れないという報告もある。

一方、**揺れるラグには適応できない。**

> **平均 40ms ± 5ms は、平均 25ms ± 20ms より気持ちいい。**

だから最適化の順序は「平均を削る」より先に**分散を削る**。具体的には、GC の発生、可変フレームレート、推論時間のばらつき、`setTimeout` 依存のスケジューリング、フレーム落ち時の可変ステップ。**平均フレームタイムではなく、フレームタイムのヒストグラムの裾を見る。**

### 主体感を上げる、遅延以外の手段

- **予兆で先出しする。**入力の確定を待たず、押し始めに小さく反応する（押し込み量に連動、ハイライト）。確定は後で来ればいい。**遅延を短くできない時、これが最も効く。**
- **写像を一貫させる。**同じ動作が毎回同じ反応を返す。乱数で反応を変えると「システムが勝手にやっている」に転ぶ。ゆらぎは**強度**に入れて、**対応**には入れない。
- **選ばせる。**やり方が1つしかない操作は、成功しても自分の功績に感じられない。
- **未検出時に「聞こえていない」を返す。**無反応は最悪。認識できていないことを示す小さな応答（薄い輪郭、低い音）を用意する。人は失敗より無視を嫌う。

## 3. 3感覚の連動 — 何をいつ揃えるか

### 揃える順序は非対称。音を映像より先に出してはいけない

視聴覚の一致の窓は左右で幅が違う。**音が映像より遅れる方向は寛容**（融合しうる範囲は +100〜170ms 程度まで）だが、**音が先行する方向は 30〜45ms で破綻する。**

実務的な結論:
- 実装遅延が読めない時は、**音をわずかに後ろに置く。**先行事故を避けられる
- 音を速くできないなら、**映像を数フレーム遅らせて音に合わせる。**両方遅いことより、ズレていることの方が気持ち悪い（`sound.md` 第4節）
- 触覚は最も速く出せる系統だが、LRA は最大振幅まで 10ms 前後かかる。**触覚のトリガは音より少し早く撃つ**

### 一致していると、片方だけより強く感じる（超加算）

これが**最も安く体験を強くする手段**である。映像の派手さを2倍にするより、同じ瞬間に音と触覚を揃える方が、体感の衝撃は大きくなる。逆に不一致は、没入感と操作精度を同時に下げる。

**設計原則: 1つの出来事 = 3感覚の同時アタック + 役割の違う減衰。**

| | アタック（揃える） | 減衰（分ける） |
|---|---|---|
| 触覚 | 最初。0〜10ms | 最短。50ms 以内に消える |
| 音 | 同時。±30ms 以内 | 中間。残響で 0.3〜3s |
| 映像 | 同時 | 最長。余波・軌跡・蓄積で数秒〜永続 |

**アタックが揃っていないと3つの別イベントになり、揃っていれば1つの出来事の3つの側面になる。**この差が「安っぽい」と「重い」を分ける。

### クロスモーダル対応 — 物理的に正しくなくても、対応が合っている方が正しく感じる

| 音 | 対応する視覚・体感 |
|---|---|
| 高音 | 小さい / 明るい / 鋭い / 上 / 軽い / 速い |
| 低音 | 大きい / 暗い / 丸い / 下 / 重い / 遅い |
| ノイズ成分が多い | 粗い表面、破断、摩擦 |
| 倍音が少ない（正弦波的） | 滑らか、人工的、清潔 |

映画の効果音で刀に金属的な高音が付くのは、物理的な正確さではなくこの対応のためである。**マッピングを決める時、この対応に逆らうと「何かおかしい」が生まれ、原因を特定できないまま作り直すことになる。**大きな物体に高い音を当てるなら、それは意図的な違和感でなければならない。

## 4. 1つのイベントを気持ちよくする（ミクロ）

打つ、掴む、離す、当たる、確定する。単発の出来事は5つの時間区間に分解できる。**このうち予兆と停止を省くのが、最も多い失敗。**

| 区間 | 役割 | 目安 | 省くとどうなる |
|---|---|---|---|
| **予兆** anticipation | これから起きると知らせる。溜め | 60〜120ms | 突然起きて、因果が読めない |
| **接触** impact | 3感覚の同時アタック | 同時（±30ms） | 出来事が3つに割れる |
| **停止** hitstop | 一瞬すべてを止める。重みはここで出る | 50〜80ms | 軽い。当たった感じがしない |
| **余波** follow-through | 慣性、揺り戻し、飛散 | 150〜300ms | 硬い。機械的 |
| **残響** residue | 痕跡、残響、蓄積 | 0.5s〜永続 | 何も起きなかったことになる |

### 動きの曲線 — 等速直線運動が「安っぽさ」の主因

- **生体の運動はジャーク（加速度の変化率）が最小になるように動く。**始点と終点で速度が0に近づく S 字が身体的に自然に見え、線形補間は「機械が動かしている」と読まれる
- **曲率が上がると速度が落ちる**のが人間の運動（2/3乗則）。カーブを描いて移動する要素を等速で走らせると生気が消える
- オーバーシュートは気持ちいいが、**繰り返す操作に入れると酔う。**確定・完了など低頻度のイベントに限る
- **100ms 未満のアニメーションは瞬間として知覚される。**変化に気づかせたいなら 100ms 以上必要。UI の実用帯は 200〜500ms、モバイルの標準は 200〜300ms

### 変化は知覚できる量にする

パラメータを 5% 動かす演出は、無いのと同じである。**知覚は比率で効く**ので、明度・音量・スケール・速度は「何%変わるか」で設計する。控えめに作った10個の反応より、はっきり分かる3個の方が気持ちいい。

### Juice の実務リスト（迷ったらこの順）

1. **hitstop**（止める）— コストゼロで最大の効果
2. **音を同時に足す**（超加算）— 発音ごとに音程を ±1〜2 半音でランダマイズすると機械的な反復感が消える
3. **スケールの squash / stretch** — 押されて潰れる、離れて伸びる
4. **画面の微小な揺れ** — 振幅は疑うほど小さくてよい。大きく揺らすのは酔いとアクセシビリティの問題になる
5. **粒子と軌跡** — 最後。これを最初にやるのが典型的な失敗
6. **同一フレームでの二重発音を潰す** — 同じ音が重なると音量が跳ねて安っぽくなる

## 5. 反復を気持ちよくする（メソ）— 予測と誤差

同じ操作を何度もする体験の快は、**予測がどれだけ当たるか**で決まる。

- **中程度のシンコペーションが最も「動きたく」させ、快も高い（逆U字）。**規則的すぎると退屈、崩しすぎると乗れない。ずれの量が設計変数である
- **人は拍の 20〜100ms 前に動く**（負の非同期）。だから**リズムの判定窓を対称に置くと厳しく感じる。**早い側を広く取った非対称な窓が体感に合う
- **溜めてから解決する。**快の頂点は解決の瞬間だけでなく、**その手前の予期**にも立つ。常に最大出力の体験には頂点が無い
- **1/f のゆらぎを入れる。**完全な規則性も完全な乱数も心地よくない。パラメータに 1/f 的な変動（音程の微差、光の揺れ、速度の呼吸）を入れると「生きている」に転ぶ。焚き火や波が心地よいのはこの構造
- **自発的なテンポは 2Hz（120BPM）近辺**が最も乗りやすい（歩行と一致）。落ち着かせたいなら 60BPM 台以下に落として呼吸に寄せる

## 6. 鎮静（落ち着く）— 生理に直接効かせる

「落ち着く」は雰囲気ではなく自律神経の状態である。**外から誘導できる。**

- **呼吸を 0.1Hz（6呼吸/分）前後に導く。**この周波数で心拍変動が最大化し、副交感が優位になる。ゆっくり膨張・収縮する視覚のペーサー、音量のスウェル、光の明滅で誘導できる。**吸気:呼気を 4:6 にする**（呼気を長くする方が効く）
- **下降を使う。**音程の下降、輝度の減衰、上から下への移動。上昇は覚醒を上げる
- **トリガを減らす。**離散的な発火は覚醒を上げる。連続的でゆるやかなパラメータ変化に置き換える
- **低域を身体に届ける。**40〜60Hz 以下は耳より体で知覚される。トランスデューサ、サブウーファー、椅子や床への伝達が「重さ」と安心を作る。ただし長時間の曝露は疲労になるので上限を決める
- **鋭いアタック、点滅、シェイクを使わない。**鎮静を狙う体験にこれらが1つ入ると、そこだけで台無しになる

## 7. 賦活（エキサイティング）— 上げるなら落とす区間を作る

**上げる順序**（先に効く順）: 密度 → テンポ → 帯域を上下同時に開く → コントラストと明度 → カメラの運動 → 数（多数性）。

**覚醒と快の関係は逆U字である。**上げ続けると報酬系ではなく嫌悪系が働き始める。だから**ピークは短く、その前後に落とす区間を必ず置く。**5分間ずっとクライマックスの体験は、退屈な体験と同じくらい快が低い。

安全側の制約は交渉不可: 点滅は毎秒3回以下（`process.md` の光過敏の警告）、カメラの大きな移動は酔い、音圧は上限を決めて掲示（`sound.md` 第9節）。

## 8. 綺麗（美しい）— 足すのではなく読みやすくする

美的な快の大部分は**処理流暢性**、つまり「読み取りやすさ」から来る。図と地のコントラスト、対称性、典型性、反復。これらは全部「早く認識できる」性質である。

- **綺麗にしたい時、要素を足すのは逆方向。**色数を減らす、同時に動く方向を揃える、階層を明確にする、フレームレートを安定させる
- **丸みは落ち着き、鋭角は緊張。**鋭い角は脅威として素早く処理される。狙いに合わせて選ぶ
- **ただし流暢すぎると退屈になる。**「綺麗だが何も起きない」の正体はこれ。流暢性で美を作り、覚醒（動き、密度、音）で退屈を避ける。**2軸で考える**
- 生体運動的な運動曲線（第4節）は、それ自体が「綺麗」に効く。等速の線形移動は美しく見えない

## 9. 楽しさ（続く）— 快感は瞬間、楽しさは反復

- **有能感 / 自律性 / 関係性**が満たされると反復が起きる。操作が簡単に習得でき、フィードバックが明確で一貫し、目標や方法に選択の余地があり、協働の余地がある構成
- **上達の余地を残す。**入力の上限に3回で貼り付く操作は、その時点で終わる。強度・方向・質・タイミングの解像度を残し、**上手い人の出力が明らかに違って見える**ようにする
- **終わりが記憶を決める。**体験全体の記憶はピークと終わり際で決まる。終了直前に何を返すかを設計する（`protocol.md` の Residue）

## 10. ハプティクス — セカンダリだが安い

- **振動の知覚感度は 250Hz 前後（200〜300Hz）が最大。**この帯域を外すと同じ電力で弱く感じる
- **触覚は単独では意味を持たない。**視覚か音と**同一イベント**として設計する。触覚だけの通知は「何か起きた」以上を伝えない
- **常に鳴っている触覚は不快になる。**接触、境界の越え、確定、失敗の4種に限る
- 実装: ネイティブは iOS Core Haptics（AHAP で強度・鋭さ・時間を設計できる）/ Android の `VibrationEffect`。**Web の Vibration API は粒度が粗く、iOS Safari では使えない**ので、Web 主体の企画では触覚を前提にしない
- **体験としては、低域スピーカーやトランスデューサ（床・椅子・壁）の方が手持ちの振動より強い。**予算があるならこちら

## 11. 気持ちよさの検証 — 感想を聞かない

**自分の手は最悪の評価者である。**制作者は自分の実装の遅延に適応（校正）済みなので、初見の人が感じる違和感を検出できない。

**初見3人・各30秒のプロトコル**（`protocol.md` Step 8 と併せて使う）
1. 何も説明せず触らせる。**最初にやったこと**を記録
2. **2回目に何を変えたか。**同じことを繰り返すなら、その操作には解像度が無い
3. **手が止まった瞬間**と、その直前に何が起きたか
4. **出てきた擬音語。**「ぐにゅ」「パキッ」「ふわ」が出るなら感覚が届いている。形容詞（「すごいですね」）しか出ないなら届いていない
5. 何も言わずに**もう一度触るか。**触らなければ負け

**要素を切って当てさせる**（原因の特定に最も効く）
- 音だけ切る → **急に安っぽくなるなら、音が仕事をしている証拠**
- hitstop だけ切る、予兆だけ切る、余波だけ切る
- 遅延を 10ms 刻みで足して、どこで気づくかを見る。**平均を足す版とジッタを足す版を別に試す**

**計測**
- フレームタイムの分散（平均ではなく裾）
- 入力から出力までの実測: **240fps のスマートフォンで、指と画面を同じ画面内に収めて撮影し、フレーム数を数える。**推定値より確実で、機材はほぼ不要
- 触った回数、無操作までの時間、再訪率

## 12. アンチパターン

- 「気持ちよさ」を狙わずに機能を足すこと / 逆に、覚醒を上げるのか下げるのかを決めずに演出を足すこと
- 平均遅延だけを最適化して**分散を放置する**こと / フレームレートが可変なまま体感を評価すること
- **音を映像より先に出すこと** / アタックが揃っていない3感覚を「連動している」と呼ぶこと
- 予兆と hitstop を省いて、粒子とシェイクで重みを出そうとすること
- 等速の線形補間で動かして「安っぽい」の原因を素材のせいにすること
- 5% の変化を演出と呼ぶこと / 控えめな反応を10個並べること
- 反応に乱数を入れて写像の一貫性を壊すこと（ゆらぎは強度に入れ、対応には入れない）
- 未検出の時に何も返さないこと（無反応は失敗より嫌われる）
- 鎮静を狙う体験に点滅・シェイク・鋭いアタックを混ぜること / 賦活を狙って上げっぱなしにすること
- 主体感を作らずに派手さで押すこと（それは騒音であり体験ではない）
- 画面の揺れや視差を、`prefers-reduced-motion` と代替なしで入れること（WCAG 2.3.3。前庭系の障害がある人には実際に体調不良を起こす）
- 制作者自身の手で気持ちよさを判定すること / 初見の人に「どうでしたか」と感想を聞いて済ませること

## 13. 出力構成（手触り・体感が成否を決める案件で、選んだモードの構成に重ねる）

1. **狙う快の型**（第1節の6つのどれか。覚醒を上げるのか下げるのか）
2. **主体感の設計**（何が入力で、何ms で、どれだけ安定して返るか。ジッタの見積もりを含む）
3. **3感覚の連動表**（1イベントについて、触覚・音・映像のアタックと減衰）
4. **単発イベントの時間構造**（予兆 / 接触 / 停止 / 余波 / 残響の各区間と数値）
5. **反復の設計**（予測と誤差。何回目まで飽きないか。何が解像度を持つか）
6. **やらないこと**（覚醒の方向に反する手段を明示的に捨てる）
7. **検証計画**（初見3人で何を見るか。何を切って当てさせるか。何を計測するか）
8. **アクセシビリティ**（reduced motion、点滅、音圧、触覚の代替）
