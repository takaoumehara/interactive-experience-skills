# 工程・事業性リファレンス

モードH(フル体験ディレクション)、モードE(プロトタイプ計画)、モードF(事業・戦略)の時に読む。

## 1. モードH: フル体験ディレクション構成

包括設計を明確に要求された場合のみ使用する。各節は該当する内容がある時だけ書く(空の見出しを埋めない)。

1. **Executive Direction** — 3〜5行。この体験が何で、なぜ今これなのか
2. **Experience Thesis** — 一文の体験命題
3. **Audience & Context** — 対象、来場文脈、滞在時間、人数動態(一人/カップル/家族/団体)
4. **Core Interaction** — Trigger → Interpretation → Response → Transformation → Residue
5. **Experience Journey** — 導入 → 学習 → 探索 → ピーク → 終了 → 余韻。各段階に所要時間と感情の目標を付ける
6. **Creative System** — ビジュアル原理、動きの性格、音響設計、光・色・素材、世界観のルール
7. **Technical Architecture** — 入力から出力までの構成とデータフロー。性能目標を数値で
8. **Physical Setup** — 空間、機材配置、導線、電源・熱、安全
9. **Prototype Roadmap** — リスクの高い仮説から順に。各段階に検証項目と成功基準
10. **Risks & Mitigations** — 各リスクに必ず対策を併記
11. **Success Metrics** — 観察可能・計測可能な指標
12. **Recommended Next Decision** — 次に決めるべき1〜3項目

## 2. モードE: プロトタイプ計画テンプレート

```
検証する仮説:      (最も不確実で、外れたら設計が変わるもの1つ)
作るもの:          (体験の核だけ。最小構成)
作らないもの:      (明示することで工数を守る)
使用技術:          (この検証に必要な最小構成。本番と同じでなくてよい)
テスト方法:        (誰に、何人に、どんな環境で、何を観察するか)
成功基準:          (数値または観察可能な行動で定義)
所要:              (日数・人員)
次段階の判断条件:  (通ったら何に進み、落ちたらどう軌道修正するか)
```

**検証すべき典型的な仮説:** 会場の照明条件で認識できるか / 説明なしで参加方法が理解されるか / 反応速度が身体感覚として自然か / 複数人参加が混乱を生まないか / 表現が数分間飽きないか / 想定スループットが出るか / 高齢者・子どもが参加できるか。

**プロトタイプの原則:** 完成品のミニチュアを作らない。1〜2週間で「体験の核」だけ動くものを作り、それを仕様書の代わりにして施主・チームと合意形成する。

## 3. モードF: 事業性の計算式

### スループットと収容
```
体験スループット(人/時) = 定員 × (60 ÷ 体験分数) × 稼働率(0.80〜0.90)
1日の上限来場者      = スループット × 営業時間 × 混雑ピーク補正(0.7〜0.85)
```
待機列の長さは「上限来場者を超える需要 × 平均待機許容時間(体験価値により10〜40分)」で成立性を判断する。待機列自体を体験化(プリショー)すると許容時間が伸びる。

### 収支の骨格
```
月間売上   = 来場者数 × 客単価(+ 物販・飲食の付帯単価)
月間費用   = 人件費 + 賃料 + 光熱費 + 保守 + コンテンツ更新 + 償却
損益分岐   = 月間固定費 ÷ (客単価 - 変動費/人)
```
**見積で抜けやすい項目:** 光熱費(LED/プロジェクター/GPUの電力は想定より大きい)、GPU・プロジェクターランプの更新(3年サイクル)、キャリブレーション工数(常設は週次)、消耗品(生花・香・紙などの実素材は週次交換)、スペアパーツ在庫、スタッフ教育、コンテンツ更新の外注費。

### 常設イマーシブの初期値(根拠のない置き数字。感度分析の出発点としてのみ使う)
客単価 2,500〜4,500円 / 損益分岐は月1.5〜3万人規模 / 初期投資回収 2〜4年。

**この3つを事業計画の根拠として提示してはいけない。**業界データではなく、計算を始めるために置くための数字である。立地・IP・面積で大きく変動する。実在施設の公表値、周辺のチケット価格、実際の見積に置き換えるまでは、**「仮置き」と明記したまま**感度分析(客単価±30%、来場者±50%で損益がどう動くか)に使う。

### 展開形態の判断
| 形態 | 適する条件 |
|---|---|
| 常設 | 立地の集客力があり、コンテンツ更新体制を持てる。初期投資が大きい |
| 巡回・ツアー | コンテンツ資産を複数都市で回収したい。可搬性を設計初期から要件化する必要 |
| 期間限定イベント | 話題性優先、スポンサー予算、リスクが低い。運用習熟が進む前に終わる |
| 常設 + 期間限定演出 | 再訪動機を作れる。ベース体験と季節演出の分離設計が必要 |
| オンライン併設 | 参加母数を広げられる。会場体験の価値を薄めない設計が条件 |

## 4. 常設運用チェックリスト

納品後に死ぬ展示を防ぐための項目。常設・長期案件では必ず通す。

**自動化**
- 電源ONから無人で本番状態になるか(自動ログイン → ウォッチドッグ → アプリ起動 → 自己診断)
- 閉館時の自動シャットダウン
- 異常検知時の自動再起動と通知

**更新性**
- 非エンジニアがコンテンツを差し替えられるか(CMS or 設定ファイル)
- 更新手順書が現場に残っているか
- 1年後・3年後に何を更新する想定か、その費用を誰が持つか

**保守性**
- 高所機材にリフトなしでアクセスできるか、できないなら足場費用を初期見積に入れたか
- スペアパーツ(プロジェクター、センサー、PC、電源)の在庫または調達リードタイム
- 単一障害点リスト(メディアサーバー、スイッチ、電源系統)と各々の代替手段

**運用**
- 現場スタッフ向けの1ページ運用手順(起動、停止、よくある症状と対処)
- 「客が困っている時にスタッフが何を言うか」のスクリプト
- 匿名の体験ログ(人数、滞在時間、インタラクション回数)を取っているか — 施主報告と次案件の武器になる

**アクセシビリティ**
- 車椅子利用者の視点高さと動線
- 光過敏(点滅・ストロボ)への警告表示と代替導線
- 聴覚・視覚に依存しない参加経路が1つ以上あるか
- 多言語対応(説明を言語に依存させない設計が最も強い)
