# 学習設計 — 何を、いつ、どれだけ、どう伝えるか

このリファレンスの内容は、運動学習研究で繰り返し確認されてきた知見に基づく。**身体学習プロダクトの失敗の大半は、技術ではなくここの設計ミスで起きる。**

## 1. 最重要 — フィードバックは多いほど良い、ではない

**依存性の問題(guidance hypothesis)。** 頻繁で精密な外部フィードバックは、練習中のパフォーマンスを向上させるが、**長期的な定着と自立を損なう。**学習者はフィードバックを頼りに動くようになり、フィードバックが無い場面(=本番、試合、審査)で崩れる。

これが意味すること: **常時リアルタイム採点は、体験としては魅力的だが、学習設計としては最悪に近い既定値である。**多くの動きアプリがこれを中心機能に据え、そして定着で結果を出せずに終わる。

実務上の対策。

- **頻度を下げる(faded feedback)** — 最初は多めに、上達に伴って減らす
- **要約フィードバック(summary)** — 1回ごとではなく、5〜10回終えてからまとめて返す。これは実装も楽で、学習効果も高い
- **帯域フィードバック(bandwidth)** — 許容範囲を外れた時だけ言う。範囲内なら黙る。**「沈黙 = できている」という規約**を学習者に伝えておく
- **学習者が要求した時に返す(self-controlled)** — 押しつけより効果が高い。「今のを見る」ボタン一つで実現でき、実装コストが最も低い改善
- **試行の直後に即座に返さない** — 数秒の空白を置き、まず自分で評価させる。自己評価能力そのものが上達の要素である

**設計判断への翻訳:** 練習後レビューを既定にし、リアルタイムは限定的な用途(安全に関わる逸脱、リズム同期など即時性が本質的な要素)に絞る。技術的にも事業的にも楽になり、学習効果は上がる。

## 2. 習得段階でフィードバックを変える

| 段階 | 状態 | 必要なフィードバック |
|---|---|---|
| **認知段階(初心者)** | 何をすべきか分かっていない。誤りが大きく多い | 少数(1つ)の大きな修正。全体像。成功の感覚。細部は禁物 |
| **連合段階(中級)** | 大枠はできる。一貫性が課題 | 誤りの原因の指摘。許容範囲の提示。ばらつきの可視化 |
| **自動化段階(上級)** | 無意識に実行できる | 微細な差、条件下での崩れ、自己評価の補助。指摘しすぎると壊れる |

**初心者に細かい数値を出すのは有害である。**「肘の角度が12.3度ずれています」は、認知段階の学習者の作業記憶を占領し、動き全体を崩す。段階が上がるほど情報を増やせる。

## 3. 注意の焦点 — 言葉が身体を変える

**外的焦点(external focus)は内的焦点(internal focus)より一貫して優れている。**これは運動学習で最も再現性の高い知見の一つ。

| 内的焦点(弱い) | 外的焦点(強い) |
|---|---|
| 「膝を伸ばして」 | 「床を押し返して」 |
| 「腕を速く振って」 | 「拳を的に飛ばして」 |
| 「体幹に力を入れて」 | 「壁を押すつもりで」 |
| 「腰を回して」 | 「ベルトのバックルを相手に向けて」 |

身体部位への意識は動作を硬くし、環境や効果への意識は動作を滑らかにする。**フィードバック文言のライブラリを作るなら、外的焦点の表現に統一する。**これは実装コストゼロで学習効果を上げられる、最も費用対効果の高い設計判断である。

計測は関節角度で行ってよい。**伝える時に言葉を変える。**計測の言語と指導の言語を分離する。

## 4. 一度に一つ

動作中の作業記憶は極端に狭い。**改善点は最大3つ、実際に取り組ませるのは1つ。**

優先順位は**根本原因から。**症状ではなく原因を指摘する。

例: 突きが流れる → 原因は前足の踏み込み不足 → 原因は構えの重心が後ろ。この時に指摘すべきは**構え**であって突きではない。突きを直そうとすると、崩れた土台の上で無理な代償動作を学習してしまう。

技能モデルの中に**因果の連鎖**を持たせ、最も上流の逸脱を選ぶ。これは `skill-modeling.md` の誤り優先順位設計と直結する。

## 5. 練習の構造

- **文脈干渉:** 同じ技を続ける(ブロック練習)は、その場では上達して見えるが定着しない。異なる技を混ぜる(ランダム練習)は、その場では下手に見えるが定着する。**「今日は下手に感じる」練習の方が効いている**ことを学習者に伝えないと離脱する
- **練習の量より質の可視化:** 回数ではなく「許容範囲内だった割合」を追う
- **成功体験の設計:** 特に初期は、できたことを明示的に返す。誤り検出システムは構造上ネガティブに偏る。**できている部分を先に言う**規約を持つ
- **セッションの長さ:** 集中を要する技能練習は15〜20分が現実的な上限。長いセッション設計は使われない

## 6. 伝え方 — 学習者を傷つけない

- **動作を対象にし、人を対象にしない。**「あなたのフォームは悪い」ではなく「この回は膝が内側に入った」
- **比較対象は他人ではなく過去の自分。**ランキングは一部の上位者を除いて動機を下げる
- **単一スコアを早期に出さない。**「62点」は情報量が少なく、動機を削り、多くの場合その数値は弁護できない。代わりに「安定してきた要素/まだばらつく要素」を出す
- **できない理由を推測しない。**システムには身体の制約も痛みも見えていない
- **不確実性を隠さない。**「この角度からは判定できませんでした」は信頼を上げる

## 7. 継続の設計

上達プロダクトの真の指標は精度ではなく**継続率**である。

- **進歩が見えること**が最大の継続要因。ただし短期の上達は非線形で停滞期がある。停滞期に「変化なし」だけを返すと離脱する。停滞期には**安定性の向上**や**ばらつきの縮小**という別の軸を見せる
- **記録の蓄積そのものが資産になる**設計(過去の自分と並べて見られる、成長の記録が残る)
- **指導者や仲間との接続**が単独アプリより強い。人が見ているという事実が継続を生む
- 保護者が払う構成なら、**保護者への報告が継続を決める。**子どもの体験より、保護者に届く進捗の質の方が解約に効く

## 8. 成果をどう検証するか

「使って楽しい」は成果ではない。最低限、次のどれかを測る。

- 一定期間後の**フィードバック無し**での実行品質(定着の測定。これが本命)
- 指導者による盲検評価の前後比較
- 許容範囲内の試行割合の推移
- 学習者が自分の誤りを自己申告できるようになったか(自己評価能力の獲得)

**練習中のスコア向上を成果と見なさない。**依存性の問題により、練習中のスコアと定着は乖離しうる。
