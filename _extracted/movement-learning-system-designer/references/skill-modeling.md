# 技能モデリング — 何を「正しい」とするか

このリファレンスは、システムが評価対象を持つ時に必ず直面する問題を扱う。**参照動画をそのまま正解とする設計は、ほぼ必ず失敗する。**

## 1. フェーズ分解

技を一つの塊として比較しない。フェーズに割り、フェーズごとに別の基準で評価する。

汎用の骨格: **準備 → 起動 → 主動作 → 極点(接触・最大点) → 回復 → 残心/終位**

例(空手の中段突き): 構え → 引き手と踏み込みの開始 → 腰の回転と腕の伸展 → 極め(最大伸展と停止) → 引き戻し → 残心の姿勢。

フェーズごとに評価すべきものが違う。準備では**位置と重心**、主動作では**順序とタイミング**、極点では**到達位置と停止**、回復では**戻りの速さと崩れ**。単一のスコアはこの違いを潰してしまう。

**フェーズ境界の検出**は技術設計の要になる(`motion-tech.md` 参照)。境界が取れないと、以降の分析はすべて崩れる。

## 2. 不変条件と可変要素を分ける

**最も重要な設計作業。**参照との差のうち、どれが「誤り」でどれが「その人の身体」かを分類する。

| 分類 | 内容 | 扱い |
|---|---|---|
| **不変条件** | それが崩れると技が成立しない | 逸脱を指摘する |
| **流派・系統による差** | 正しさが複数ある | 基準を選択可能にする。誤りにしない |
| **体格・身体構造による差** | 手足の長さ、可動域、年齢 | 正規化する。誤りにしない |
| **個性・表現** | その人らしさ | 触らない |

**分類作業は指導者としか行えない。**技術者だけで決めると、必ず「参照動画との数値差」を誤りと見なす設計になる。企画の早い段階で、指導者に「この差は直すべきか、その人の身体か」を実例で判定してもらう工程を入れる。

**警戒サイン:** 参照動画が1本しかない。それは「1人の、ある1回の実行」であって基準ではない。最低でも同一指導者の複数回、可能なら複数の熟練者を集めて**ばらつきの幅そのものを基準にする。**

## 3. 許容範囲(トレランス)

二値の正誤判定をしない。範囲で持つ。

- 各評価項目に**許容帯**を設ける。帯の中なら黙る(`learning-design.md` の帯域フィードバック)
- **習熟度で帯幅を変える。**初心者に上級者の帯を適用すると、常に全項目が赤になり離脱する
- 帯の外側にさらに**「明らかな逸脱」帯**を置く。ここだけは初心者にも即座に伝える(特に安全に関わるもの)
- **帯は熟練者のばらつきから導く**のが最も正当。3〜5人の熟練者の実行から分散を取り、それを基準帯とする

## 4. 重要度と因果の連鎖

すべての逸脱を同格に扱わない。**重要度**と**因果の上下関係**を持たせる。

```
構えの重心が後ろ  ← 根本
   └→ 踏み込みが浅い
        └→ 腰の回転が不足
             └→ 突きが流れる  ← 症状(最も目立つ)
```

出力すべきは**根本**であって症状ではない。技能モデルに依存関係を持たせ、逸脱が複数検出された時に最上流のものを選ぶロジックを入れる。これが無いと、システムは常に最も目立つ症状を指摘し、指導者から見て素人臭い出力になる。

重要度は3層程度で十分: **安全に関わる / 技の成立に関わる / 洗練に関わる。**初心者には上2層のみを出す。

## 5. 体格の正規化

**絶対座標で比較しない。**身長・手足の長さ・体格が違えば、同じ動きでも座標は一致しない。

使うべき特徴量。

- **関節角度** — 身長に不変。最も基本かつ堅牢
- **比率** — 歩幅÷身長、手の到達距離÷腕長、重心高÷身長
- **相対位置** — 拳の位置を「肩を原点とし肩幅で正規化した座標」で表す
- **タイミングの比率** — 各フェーズの絶対秒数ではなく、全体に対する割合
- **順序** — どの関節がどの順で動き出したか(これは寸法に完全に不変で、技の質を最もよく表す)

年齢・体格差が大きい対象(子ども)では、正規化の設計が精度以上に効く。子どもの動きを大人の参照と比べて「不足」と出すシステムは、指導者から即座に否定される。

## 6. 流派差の扱い — 誰の基準か

**同じ技に対して3人の指導者が異なる指摘をするなら、そのシステムは唯一の「正解」を持てない。**これは技術で解決する問題ではなく、プロダクト設計で解決する問題である。

取りうる設計。

| 方式 | 内容 | 適する場面 |
|---|---|---|
| **出典明示** | 「〇〇流・△△師範の基準」と明記して比較する | 単一道場向け。最も誠実で最も摩擦が少ない |
| **指導者オーサリング** | 指導者が自分の実行を登録し、それを基準にする | B2B道場ツールの中核機能になりうる。**指導者を味方にする最強の設計** |
| **共通項のみ評価** | 流派を問わず共通する要素だけを対象にする | 汎用アプリ。評価できる範囲は狭くなるが、否定されにくい |
| **複数基準の並置** | 差を「誤り」ではなく「流派による違い」として見せる | 教育・研究用途。それ自体が価値になる |

**避けるべき:** システムが匿名の「正しいフォーム」を持ち、それに従わせること。これは指導者の権威と直接衝突し、導入の最大の障壁になる。

指導者オーサリングは、技術的には「参照シーケンスの記録と特徴量抽出」だけで実現でき、事業的には**その道場でしか使えない資産**を作るため乗り換えコストにもなる。個人開発規模でも実装可能で、投資対効果が最も高い機能の一つ。

## 7. 評価ルーブリックの設計

指導者と共同で作る。技術者だけで作らない。

各項目に持たせるもの:

```
項目名:        極めの停止
フェーズ:      極点
何を見るか:    最大伸展後、拳の速度が0.1秒以内にほぼ0になるか
不変/可変:     不変条件(流派を問わず)
重要度:        技の成立
許容帯:        熟練者5名の分散 ±2SD
根本/症状:     症状(原因は踏み込みと体幹の固定にありうる)
観測可能性:    高(横からのカメラ、60fps以上が必要)
伝える言葉:    「拳を的の1cm先で止めるつもりで」(外的焦点)
判定不能条件:  手首のランドマーク信頼度 < 0.7、または横方向の視野外
```

**「判定不能条件」を必ず持つ。**これが確信度制御(コア原則4)の実装単位になる。

## 8. 対象を絞る勇気

**すべての技を評価しようとしない。**評価対象を1つの技に絞り、それを完璧に扱うシステムは、10の技を曖昧に扱うシステムより、指導者からも学習者からも高く評価される。

選定基準: 頻度が高い(初心者が最初に習う) / カメラで観測しやすい / 誤りのパターンが明確で数が限られる / 指導者が「毎回同じことを言っている」と感じている技。

**最後の基準が最も強い。**指導者が繰り返し言っている指摘は、自動化の価値が最も高く、正解の合意も取れている。企画の最初に指導者へ「毎回同じことを言わされているのは何ですか」と聞くのが、この領域で最も効率の良い質問である。
