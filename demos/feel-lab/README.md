# 手触りの診断台 (feel-lab)

`interactive-experience-collective` の `pleasure.md` / `feel.md` に書いた原理を、**実際に手で確かめるための単一HTML。**依存なし、ビルドなし。`index.html` をブラウザで開くだけで動く。

```
open demos/feel-lab/index.html
```

## これは何か

**インタラクションは1つだけ**（押す → 溜まる → 離す → 場が割れる → 痕跡が残る）。その1つに対して、気持ちよさを作っている要素を**個別に切れる**ようにしてある。

リファレンスの主張が現実に合っているかを、自分の指で検証するための台である。デモとして見せるものではなく、**判断を訓練するための道具**として作った。

## 触る順序（これが本体）

1. **まず何も切らずに数回押して離す。**基準を作る
2. **音をONにする** — `sound.md` / `pleasure.md` 第3節の超加算。映像は1ピクセルも変えていないのに、衝撃が変わる。ここで「安っぽさ」の半分が音の不在だったと分かる
3. **予兆を切る** — 溜めが消える。同じ結果が返るのに「突然起きて因果が読めない」になる
4. **停止を切る** — hitstop 60ms が消える。当たりが軽くなる。粒子の数も色も同じままなのに軽い
5. **遅延を「一定 +40ms」にする** — 数回触ると身体が校正して、意外と気にならなくなる
6. **遅延を「揺れ 20±20ms」にする** — **平均は 20ms で、一定 40ms の半分。それでもこちらの方が気持ちよくない。**これが「平均より先に分散を削る」の実物
7. **曲線を「等速」にする** — 最小ジャーク風の easeOut が linear になる。衝撃波も粒子も等速になり、生気が消える
8. **覚醒を「鎮静」にする** — 同じ入力・同じ構造のまま、狙う情動だけを反転させた版。呼吸のペーサー（10秒周期、吸気4秒:呼気6秒 = 0.1Hz）、下降する音程、鋭いアタックとシェイクの停止

## 読み値

| 表示 | 意味 |
|---|---|
| `frame p50` / `p95` | フレームタイムの中央値と95パーセンタイル。**この差が開いているほど手触りが壊れる。**平均だけ見ても分からない |
| `入力→描画` | pointerdown の `event.timeStamp` から、それが適用されて描かれるまでの実測値。人工遅延を入れるとここに乗る |
| `打数` | 反復した回数。3回で飽きるか、20回続くか |

`p95 − p50` が 8ms を超えると赤くなる。

## 実装で守っていること（コード内にコメントあり）

- **マスターに必ずリミッター**を1段（`DynamicsCompressorNode`）。同時発音で 1.0 を超える
- **ボイススティール** — 上限に達したら古い音を減衰させる。新しい発音を捨てない
- **音程はペンタトニックに拘束**し、発音ごとに ±12 cent 程度デチューン
- **ルートが 40秒周期で動く** — 同じマッピングのまま景色が変わる
- **溜めの音はアタックを遅く**（280ms）して遅延を隠す。接触音は 4ms
- **触覚は音より先に撃つ** — LRA は最大振幅まで 10ms 前後かかる
- **1/f のゆらぎ** — 無理数比の正弦を3本重ねて、地の明度と痕跡の漂いに入れている
- **直接操作の層と遅い層を分ける** — 芯は指に貼り付き、場の輪は 170ms 遅れて追う
- **`prefers-reduced-motion`** を検出したら、画面の揺れと閃光を止め、粒子を減らす
- **キーボードでも操作できる**（Space / Enter）。ポインタ専用にしない

## 既知の制約

- **触覚は Android Chrome のみ。**iOS Safari は Vibration API 非対応なので、その端末ではスイッチが無効になる。ネイティブなら Core Haptics（`pleasure.md` 第10節）
- **音は必ずユーザー操作のあとに解錠される**ため、既定はOFF。スイッチを押した時点で `AudioContext` を作って `resume()` する
- 人工遅延は**再現のための機能**であって、実装遅延そのものではない。実測値は `入力→描画` に出る
- スマートフォンの実機では、ブラウザの合成遅延が数十ms乗る。**この台で「なし」に見えている状態も、実機では 0ms ではない**
